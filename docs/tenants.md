# 입주 규칙

이 서버에 프로젝트를 올리는 팀을 위한 문서. 배경은 [ADR 0009](adr/0009-tenant-isolation-and-predeploy-check.md).

## 우리가 제공하는 것 / 팀이 책임지는 것

| 제공 | 팀 책임 |
|---|---|
| 서버 자원(배정된 상한 안에서) | 이미지 빌드와 레지스트리 |
| 배포 화면(Komodo): 배포·로그·터미널 | 자기 레포의 `compose.yaml` |
| 대시보드(Grafana): 프로젝트 폴더 | DB 종류 선택과 스키마, 마이그레이션 |
| 외부 공개 도메인과 인증서 | 앱의 지표·로그·트레이스 내보내기(OTLP) |
| DB 백업(정해진 주기) | 비밀값 내용 |

## 받는 것

- **포트 대역** 100개 (예: 10000~10099). 공개하는 포트는 이 안에서만.
- **Docker 네트워크** 하나. 다른 프로젝트의 컨테이너와 통신할 수 없다.
- **자원 상한** (CPU·메모리). 프로젝트 합계 기준.
- **Tailscale 접근**: 자기 포트 대역과 Grafana·Komodo 화면. 기기 공유로 초대한다.
- **로그인**: GitHub 계정(Keycloak 경유).

서버 OS 계정은 제공하지 않는다. 컨테이너 안을 봐야 하면 Komodo의 터미널을 쓴다.

## 배포

1. 팀 레포에서 이미지를 빌드해 레지스트리에 올린다.
2. Komodo에서 자기 스택의 Deploy를 누른다(또는 새 이미지 자동 감지).
3. 배포 전 검사가 compose를 확인한다. 걸리면 배포가 중단되고 이유가 로그에 남는다.

## compose에서 허용되지 않는 것

| 항목 | 대신 |
|---|---|
| `privileged`, 위험한 `cap_add` | 필요한 이유를 알려 주면 대안을 같이 찾는다 |
| `network_mode: host`, `pid: host` | 배정된 네트워크와 포트 대역 |
| Docker 소켓 마운트 | 허용하지 않음 |
| 스택 폴더 밖 경로 마운트 | named volume |
| 대역 밖 포트 | 대역 안 포트 |
| 자원 상한 없는 서비스 | `deploy.resources.limits` 또는 `mem_limit` |

## 요청이 필요한 일

관리자에게 요청한다(이슈 또는 메신저). 비밀값은 이슈에 쓰지 않는다.

- 환경 변수·비밀값 추가와 변경
- 외부 공개 도메인 추가
- 자원 상한·포트 대역 조정
- 규칙의 예외 — 승인되면 `tenants/<프로젝트>/policy.yml`에 항목과 사유가 기록된다

## 새 프로젝트를 받을 때 (관리자용)

1. 포트 대역 배정 → `tenants/<프로젝트>/policy.yml` 작성
2. Keycloak 그룹, Grafana 폴더, Komodo 스택과 권한 생성
3. Tailscale 접근 규칙에 대역 추가(`terraform/tailscale/`)
4. 팀원 기기 공유 초대
