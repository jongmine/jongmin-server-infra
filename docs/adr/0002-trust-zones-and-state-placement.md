# 0002. 신뢰 구역과 상태 배치

상태: 확정 · 2026-11-24

## 배경

클라우드와 집에 서버가 나뉘어 있는데, 무엇을 어디에 둘지 기준이 없었다.
기준 없이 배치하면 "남는 서버에 올린다"가 되어 경계가 흐려진다.

## 결정

두 가지 기준으로 배치한다.

**1. 신뢰 구역** — 누가 닿을 수 있는가로 서버를 나눈다.

| 구역 | 서버 | 닿는 주체 |
|---|---|---|
| edge | marshall | 인터넷 전체 |
| workload | gibson | 관리자 + 입주팀 |
| platform | fender | 관리자 (입주팀은 Grafana 등 지정된 화면만) |

한 서버는 한 구역에만 속한다. 구역 사이 통신은 Tailscale 접근 규칙으로 허용한 것만 된다.

**2. 상태 배치** — 잃으면 안 되는 데이터(DB, 지표, 계정)는 집에 둔다.
marshall에는 지워도 코드로 다시 만들 수 있는 것만 둔다.

## 결과

- marshall이 침해되어도 데이터가 없다. 새 VM을 만들고 Ansible을 다시 돌리면 복구된다.
- 입주팀 컨테이너가 관측·인증·배포 관리 도구와 같은 서버에 있지 않다.
- 비용: 요청이 marshall → Tailscale → 집으로 한 번 더 건너간다. 집 인터넷이 끊기면 서비스도 끊긴다.
- 관측 스택이 workload와 다른 서버라, gibson이 죽어도 무슨 일이 있었는지 볼 수 있다.

## 검토한 대안

- 전부 클라우드: 무료 범위를 넘고, 집 서버를 쓰는 의미가 없어진다.
- 역할 구분 없이 자원 여유에 따라 배치: 권한과 방화벽 규칙을 서버 단위로 쓸 수 없게 된다.
