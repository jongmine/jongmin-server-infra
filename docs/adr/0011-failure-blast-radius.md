# 0011. 노드 장애는 이중화하지 않고 피해 범위를 가둔다

상태: 확정 · 2026-11-25

## 배경

서버마다 역할이 하나라 모든 서버가 그 역할의 단일 장애 지점(SPOF)이다.
한 대가 죽었을 때 전체가 멈추는지, 역할을 다시 나눠야 하는지를 검토했다.

## 결정

**이중화하지 않는다. 한 대가 죽으면 그 역할만 멈추게 한다.**

| 죽는 것 | 외부 사용자 | 팀원(Tailscale) | 알림 |
|---|---|---|---|
| fender | 영향 없음 | 대시보드·배포 버튼만 불가 | 오지 않음 |
| gibson | 입주 서비스 중단 | 입주 서비스 중단 | fender가 보냄 |
| marshall | 전부 끊김 | 정상 | fender가 보냄 |
| 집 인터넷·전원 | 전부 끊김 | 전부 끊김 | 오지 않음 |

fender의 장애가 "기능 저하"로 끝나도록 다음을 지킨다. **fender는 요청 처리 경로에 두지 않는다.**

- 공개 서비스의 라우트에 Keycloak 인증을 걸지 않는다. Keycloak은 관리 화면 전용이다.
- 앱은 지표·로그·트레이스를 자기 서버의 Alloy에만 보낸다. fender에 닿지 않으면 버린다(앱이 막히지 않는다).
- Komodo가 멈춰도 떠 있는 컨테이너는 계속 돈다. 급하면 서버에서 `docker compose`로 직접 다룬다.

이 조건은 장애 시험으로 확인한다. 2단계 이후의 명세는 완료 조건에
"해당 서버를 끈 상태에서 나머지가 위 표대로 동작한다"를 넣는다.

## 받아들이는 것

- marshall이 죽으면 복구할 때까지 외부 접속이 없다. 상태가 없으므로 Terraform과 Ansible로 다시 만든다.
- 집 인터넷과 전원은 하나뿐이다. 줄일 방법이 없다.
- fender나 집 전체가 죽으면 알림이 오지 않는다. 집 밖에서 지켜보는 감시는 두지 않는다
  (외부 점검 서비스를 검토했으나 홈랩 규모에서 우선순위가 낮아 제외).

## 검토한 대안

- 역할을 합침: 한 대가 죽을 때 잃는 것이 늘어난다.
- 앱을 두 서버에 이중화: DB 복제와 자동 전환이 필요하다. [0001](0001-compose-over-kubernetes.md)에서 뺀 부담이 돌아온다.
- OCI에 VM을 한 대 더: 무료 DNS에는 상태 점검이 없어 전환이 자동이 되지 않는다.

## 다시 검토할 때

- marshall 구축(3단계) 시: gibson에 Cloudflare Tunnel을 꺼 둔 채 두고 DNS를 수동 전환하는 비상 우회로.
- gibson 정리(4단계) 시: gibson이 죽었을 때 fender에 임시로 올리는 절차를 runbook으로.
