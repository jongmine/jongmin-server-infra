# 0007. 비밀값은 ansible-vault

상태: 확정 · 2026-11-24 (보관 위치는 미정)

## 배경

비밀값 파일을 `.gitignore`에 두고 로컬에만 보관했더니 파일을 잃어버린 적이 있다.
레포는 공개다. 배포를 Komodo가 하게 되면서 compose가 비밀값을 받는 경로도 정해야 했다.

## 결정

**ansible-vault 하나로 관리한다.**

흐름:

```
vault 파일 ──Ansible──▶ 서버별 Komodo Periphery 설정의 [secrets]
          ──▶ 스택 Environment의 KEY=[[KEY]] ──▶ compose에서 ${KEY}
```

compose 파일 안의 `[[KEY]]`가 치환되는지는 확인하지 못했다. Environment를 거치는 쪽이 문서화된 경로다.

- vault 변수는 `vault_` 접두사를 붙이고, 평문 변수 파일에서 `변수: "{{ vault_변수 }}"`로 받는다.
  (어떤 변수가 있는지는 평문 파일에서 검색되고, 값만 암호화된다.)
- 서버는 **자기에게 필요한 비밀값만** 받는다. 그룹·호스트 단위로 나눈다.
- vault 비밀번호의 원본은 암호 관리 앱에, 자동화용 사본은 Mac 로그인 키체인에 둔다.
  Ansible은 `--vault-password-file` 스크립트로 키체인에서 읽는다.
- **입주팀의 비밀값은 이 레포에 넣지 않는다.** 팀이 값을 전달하면 관리자가 Komodo 스택의
  환경 변수에 넣는다. 팀에 스택 설정 권한을 주면 배포 전 검사도 끌 수 있기 때문이다([0009](0009-tenant-isolation-and-predeploy-check.md)).
- 옛 구조에서 쓰던 값은 해당 서비스가 새 구조로 넘어갈 때 새로 발급한다.

## 미정

암호화된 vault 파일을 어디에 둘지: ① 이 공개 레포에 커밋 ② 비공개 레포 ③ 로컬 + 별도 백업.
명세 `1-02`에서 결정한다.

## 결과

- 도구를 늘리지 않는다. Ansible을 쓰는 한 추가 설치가 없다.
- 비용: 파일 전체가 암호화되어 diff로 무엇이 바뀌었는지 보이지 않는다.
  Mac을 바꾸면 키체인 항목을 다시 넣어야 한다(원본은 암호 관리 앱에 있음).

## 검토한 대안

- SOPS + age: 값만 암호화되어 diff가 보인다. Ansible을 계속 쓰므로 도구를 더하지 않기로 했다.
- Vault/Infisical 같은 비밀값 서버: 운영할 서비스가 하나 늘어난다. 규모에 비해 과하다.
