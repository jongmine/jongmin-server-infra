# 0005. SSO는 Keycloak

상태: 확정 · 2026-11-24

## 배경

관리 화면마다 계정이 따로였고, 일부는 프록시의 Basic Auth 하나로 보호했다.
입주팀원에게 "자기 프로젝트의 대시보드와 배포 화면만" 보여 주려면 사용자와 그룹을
한 곳에서 관리해야 한다.

## 결정

**Keycloak을 fender에 둔다.**

- 로그인은 GitHub 계정 연동을 기본으로 한다(팀원이 비밀번호를 새로 만들지 않도록).
- 그룹은 프로젝트 단위로 만든다. 그룹 → Grafana 폴더 권한, 그룹 → Komodo 권한으로 연결한다.
- 첫 연결 대상은 Grafana, 다음은 Komodo다.
- DB는 Keycloak 전용 Postgres를 같은 compose 안에 둔다(서비스별 DB 분리).

fender에 두는 이유: 계정 데이터는 상태이므로 집에 둔다([0002](0002-trust-zones-and-state-placement.md)).
입주팀 컨테이너와 같은 서버에 인증 서버를 두지 않는다.

## 결과

- **관측 데이터는 프로젝트 사이에 격리하지 않는다.** 폴더 권한은 대시보드만 가리고, 조회 권한이 있는
  사용자는 다른 프로젝트의 로그와 지표도 조회할 수 있다. 입주팀이 서로 신뢰하는 동안은 받아들인다.
  서로 모르는 팀이 들어오면 프로젝트별 Grafana 조직과 저장소 수준 분리를 검토한다.
- 팀원 추가·제거가 그룹 한 곳에서 끝난다.
- 포트폴리오 관점에서 OIDC 연동을 실제로 운영한 경험이 남는다.
- 비용: N100에서 메모리 약 0.5~1GB를 쓴다. Keycloak이 멈추면 SSO 로그인이 막히므로
  Grafana와 Komodo에 로컬 관리자 계정을 비상용으로 남긴다.

## 검토한 대안

- Authentik, Authelia: 더 가볍다. Keycloak을 고른 이유는 실무에서 가장 흔히 만나는 도구이기 때문.
- 도입하지 않음: 연결 대상이 둘뿐이라 과할 수 있다는 점은 인정한다. 입주팀 권한 분리 요구로 도입.
