# 1-04 배포 전 검사 스크립트

상태: 대기 · 마일스톤: 1

## 목적

입주 프로젝트의 compose가 서버 격리를 깨지 않는지 배포 전에 검사하는 스크립트를 만든다.
Komodo에 연결하는 것은 2단계다. 여기서는 **스크립트와 그 시험**을 레포에서 완성한다.

## 구현 전에 사용자가 정할 것

구현 언어. 선택지(셸 + `yq`, Python, conftest/OPA)별 스케치와 장단점을 제시하고 고르게 한다.
서버에 추가 설치가 필요한지, 시험을 쓰기 쉬운지가 기준이다.

## 범위 밖

- Komodo `pre_deploy` 훅 연결과 실제 배포 중단 시험(2단계, Komodo 구축 직후).
- 관리자 스택(`stacks/`)에 대한 검사. 이 검사는 입주 프로젝트용이다.
- 이미지 취약점 스캔, 이미지 출처 제한.

## 만들 것

- `policy/check-compose` — 입력: compose 파일 경로, 정책 파일 경로. 위반이 있으면 종료 코드 1과
  위반 목록(서비스 이름, 항목, 이유)을 출력.
- `tenants/sallang/policy.yml` — 포트 대역(10000~10099), 자원 상한, 예외 목록(처음엔 비어 있음).
- `policy/tests/` — 통과해야 하는 compose와 거부되어야 하는 compose, 그리고 전부 돌리는 실행 파일.

검사는 `docker compose config`로 **해석을 마친 결과**에 대해 한다
(`extends`, 환경 변수 치환, 짧은/긴 문법 차이로 우회되지 않도록).

## 완료 조건

`policy/tests/run` 한 번으로 아래가 모두 확인된다.

1. 규칙을 지킨 compose → 종료 코드 0.
2. 아래 각각을 **하나만** 위반한 compose → 종료 코드 1, 출력에 해당 항목 이름이 있다.
   - `privileged: true`
   - `network_mode: host`
   - `pid: host`
   - Docker 소켓 마운트 (짧은 문법과 긴 문법 둘 다)
   - 스택 폴더 밖 bind mount (`../`로 벗어나는 상대 경로 포함)
   - 최상위 `volumes`의 `driver_opts`(`o: bind`, `device: <경로>`)로 스택 폴더 밖 경로를 가리키는 named volume
   - 대역 밖 포트 공개 (`"8080:80"`, 긴 문법, 범위 `"10090-10110:..."` 포함)
   - 메모리 상한 없는 서비스
   - 서비스 메모리 상한에 `deploy.replicas`(없으면 1)를 곱한 합이 정책 파일의 프로젝트 상한을 넘음
     (`replicas: 3`으로만 넘는 경우를 따로 시험)
   - `cap_add`에 `SYS_ADMIN`, `CAP_SYS_ADMIN`, `ALL` (각각 따로 시험)
3. 정책 파일의 예외에 적힌 항목(예: 특정 서비스의 스택 폴더 밖 특정 경로 읽기 전용 마운트)은 통과한다.
4. 예외에 Docker 소켓, `privileged`, 대역 밖 포트를 적어도 여전히 거부된다.
5. 문법이 틀린 compose나 없는 정책 파일 → 종료 코드 1 (열린 채로 통과하지 않는다).
6. 위반이 둘 이상이면 전부 출력한다(하나 고치고 다시 걸리는 일을 줄인다).

Red 확인: 스크립트를 "항상 0을 반환"으로 둔 상태에서 `policy/tests/run`이 실패해야 한다.
이 출력을 PR에 남긴다 — 시험이 실제로 무언가를 잡는다는 증거다.

## 전환과 되돌리기

서버에 영향이 없다. 되돌리기는 PR revert.
sallang의 현재 compose가 이 검사를 통과하는지는 여기서 강제하지 않는다. 결과만 확인해
팀과 협의할 목록으로 사용자에게 전달한다(공개 이슈에 쓰지 않는다).
